# Sylabus roboczy — Wprowadzenie do technologii internetowych
**Uczelnia:** Vistula  
**Semestr:** zimowy 2026/2027 (01.10.2026–12.02.2027)  
**Prowadzący:** Jakub Sitek  
**Wymiar:** 10 godzin dydaktycznych wykładu + 14 godzin dydaktycznych laboratorium.  
**Status:** plan dydaktyczny do wykorzystania przy prowadzeniu zajęć; formalny sylabus uczelni i regulamin mają pierwszeństwo.

## Cele
- Zrozumienie działania internetu i aplikacji webowych w modelu klient–serwer.
- Budowa statycznej i interaktywnej strony HTML/CSS/JavaScript.
- Poznanie DOM, JSON, asynchronicznego pobierania danych przez fetch i podstaw REST.
- Publikowanie projektu z wykorzystaniem Git i GitHub Pages.
- Poznanie podstaw backendu, baz danych i bezpieczeństwa aplikacji webowych.

## Efekty uczenia się
**Wiedza:** student opisuje HTTP/HTTPS, URL, HTML, CSS, JavaScript, DOM, JSON, REST, relacje w bazie danych oraz podstawowe ryzyka bezpieczeństwa.
**Umiejętności:** student tworzy i publikuje stronę, wykorzystuje responsywny CSS, obsługuje zdarzenia i DOM, pobiera JSON przez fetch, rozpoznaje błędy w konsoli i narzędziach developerskich.
**Kompetencje:** student dokumentuje pracę w GitHub, wykorzystuje materiały techniczne i narzędzia AI krytycznie, potrafi wyjaśnić własne rozwiązania w zakresie wybranej ścieżki.

## Wykłady
1. W1 (2,5 h): Internet, WWW, DNS, URL, model klient–serwer, protokół HTTP/HTTPS, HTML5, Git i hosting.
2. W2 (2,5 h): CSS3 — kaskada, selektory, box model, Flexbox, Grid, responsywność i dostępność.
3. W3 (2,5 h): JavaScript — typy danych, funkcje, tablice, obiekty, zdarzenia, DOM, formularze.
4. W4 (2,5 h): JSON, Promise/async-await, fetch, REST, statusy HTTP, CORS, backend, SQL, Supabase, RLS i bezpieczne wykorzystanie AI.

## Laboratoria
1. L1 (2 h): CV HTML5, repozytorium i GitHub Pages.
2. L2 (2 h): CSS, układ responsywny CV.
3. L3 (2 h): JavaScript i interaktywne CV.
4. L4 (2 h): JSON, fetch, dynamiczne budowanie CV przez DOM; standardowy termin ukończenia pakietu podstawowego.
5. L5 (3 h): prezentacje indywidualne, konsultacje i poprawki.
6. L6 (3 h): prezentacje indywidualne, konsultacje i zakończenie oceniania.

## Warunki zaliczenia
**3,0:** działające zadania CV 1–4, repozytorium, GitHub Pages, zgłoszenie linków. Bez standardowej indywidualnej obrony. AI dopuszczalne.
**4,0:** 3,0 oraz (A) udokumentowany zaakceptowany kurs Coursera/równoważny program nauki, lub (B) rozszerzenie CV o formularz, walidację i localStorage. W obu wariantach wymagana jest pełna indywidualna obrona CV i opanowanego materiału: teoria, analiza kodu, wyjaśnienia, modyfikacje i debugowanie na polecenie prowadzącego. Liczba pytań i zmian nie jest ograniczona do jednej.
**5,0:** spełnienie **wszystkich wymagań na 4,0 (ścieżka A lub B łącznie z obroną)** oraz aplikacja Biblioteka autorzy–książki oparta o bazę danych i API (preferowane GitHub Pages + Supabase), a także rozszerzona obrona projektu: teoria, architektura, analiza kodu, prezentacja, wyjaśnianie błędów i modyfikacje bez sztywnego limitu.
**3,5 / 4,5:** możliwe jako oceny pośrednie zależnie od stopnia realizacji wymagań i wykazanych umiejętności.
Nie ma obowiązku płacenia za kurs ani kupowania certyfikatu. Równoważne bezpłatne rozwiązania są dopuszczalne.

## Termin i elastyczność
Zadania podstawowe można oddać w dowolnym momencie, nie później niż do końca L4. Po potwierdzeniu zaliczenia podstawowego dalsze konsultacje projektowe nie są konieczne; formalna obecność i zaliczenie wykładu/laboratorium podlegają regulaminowi uczelni. Terminy indywidualnych obron ustala prowadzący w obrębie L5–L6.

## Ocenianie praktyczne
Działające wdrożenie; poprawność i kompletność; podczas obrony na 4,0 i 5,0 szczegółowe rozumienie architektury, kodu i przepływu danych, odpowiedzi na pytania z teorii, modyfikacje i debugowanie według poleceń prowadzącego. Uwierzytelnianie i RLS w Supabase są zalecane, ale nie należą do wymaganych funkcji projektu demonstracyjnego. Nie wolno ujawniać kluczy secret/service_role. Nie sprawdza się autorstwa pojedynczych linijek kodu metodą detekcji AI.
