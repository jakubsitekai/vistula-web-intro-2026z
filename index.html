Cel i organizacja

Poznasz podstawy działania aplikacji internetowych: strukturę stron, ich stylowanie, interaktywność, pobieranie danych, API i podstawy komunikacji z backendem. Projekt podstawowy można ukończyć wcześniej, nie trzeba czekać na kolejne laboratoria.

Cel praktyczny

Od HTML do aplikacji

Na początku statyczna strona CV, na końcu strona pobierająca JSON i budująca treść z użyciem DOM.

Samodzielna nauka

Różne poziomy zaangażowania

Wybierz podstawowe zadania, kurs lub rozbudowany projekt. Coursera jest rekomendowana, ale nieobowiązkowa.

Zasada uczciwego oceniania: na 3,0 sprawdzana jest kompletność i działanie oddanego rozwiązania. Przy ocenie 4,0 i 5,0 jest pełna indywidualna obrona: pytania z teorii, wyjaśnianie działania kodu i zmiany wskazane przez prowadzącego, bez sztywnego limitu liczby zmian. Samo korzystanie z AI nie obniża oceny.

Zadania obowiązkowe — wspólna podstawa

Cztery zadania tworzą jedną ścieżkę. Każda wersja powinna dać się uruchomić oddzielnie z katalogu zad1, zad2, zad3 i zad4. Wszystkie cztery są wymagane niezależnie od docelowej oceny.

L1 · HTML

Zadanie 1 — moje CV

Plik zad1/index.html, poprawne HTML5 i znaczniki semantyczne. Nagłówek, krótki opis, wykształcenie, doświadczenie, umiejętności, lista i co najmniej jeden link. Dane mogą być całkowicie fikcyjne.

Weryfikacja: strona wyświetla się bez JS i CSS.

L2 · CSS

Zadanie 2 — wygląd i mobile

Kopia/rozwinięcie CV w zad2. Oddzielny plik style.css, zróżnicowane nagłówki i sekcje, marginesy/padding, własne kolory, Flexbox lub Grid i układ dostosowany do telefonu.

Weryfikacja: strona czytelna na telefonie i komputerze.

L3 · JS

Zadanie 3 — interakcje

Katalog zad3, oddzielny script.js. Co najmniej dwie interakcje obsługiwane zdarzeniami JavaScript: zmiana motywu, rozwijanie sekcji, filtrowanie kompetencji, pokaż/ukryj dane.

Weryfikacja: reakcje na kliknięcia i brak błędów w konsoli.

L4 · DOM & fetch

Zadanie 4 — dynamiczne CV

Pliki zad4/index.html, script.js i cv.json. Dane sekcji CV pochodzą z JSON-u serwowanego przez GitHub Pages. fetch() pobiera JSON, a JavaScript buduje DOM i wyświetla dane. Dodać komunikat ładowania i błędu.

Weryfikacja: zmiana JSON zmienia widoczne CV bez edycji HTML.

Wskazówka: w zadaniu 4 użyj adresu względnego fetch('./cv.json'), aby JSON był pobierany z tego samego katalogu i hosta GitHub Pages. Serwer zwraca JSON, a nie JavaScript.

Wymagany jest link do publicznego repozytorium oraz działającej strony GitHub Pages (np. bezpośrednio do /zad4/). Sam zrzut ekranu nie wystarcza.

Zaliczenie i ocenianie

3,0 · podstawowe zaliczenie

Cztery wersje CV

Wykonanie zadań 1–4 i przekazanie działających linków. Nie przewiduje się obowiązkowej indywidualnej obrony. Można korzystać z AI. Sprawdzana jest kompletność rozwiązania, nie autorstwo poszczególnych linijek.

4,0 · dwie równoważne ścieżki

Kurs albo rozszerzenie CV

A: po CV 1–4 ukończ zaakceptowany kurs Coursera lub równoważny materiał i przedstaw potwierdzenie wykonania.

B: po CV 1–4 dodaj edycję danych przez formularz, walidację, zapis i odczyt z localStorage.

Obowiązkowa obrona w obu ścieżkach: omówienie działania własnego CV, pytania z teorii (i z kursu lub rozszerzenia), wskazywanie fragmentów kodu, modyfikacje i debugowanie na polecenie prowadzącego. Nie ma limitu jednej zmiany; dostarczenie kursu lub projektu nie przesądza automatycznie o ocenie dobrej.

5,0 · projekt zaawansowany

Aplikacja Biblioteka

CV 1–4 oraz komplet jednej ze ścieżek na 4,0 (A albo B), a następnie aplikacja autorzy–książki z bazą Supabase i CRUD. Wymagana jest pełna indywidualna obrona: architektura, teoria, demonstracja działania, analiza błędów i modyfikacje kodu według poleceń prowadzącego. Szczegóły poniżej.

3,5 i 4,5

Oceny pośrednie

Możliwe na podstawie zakresu, poprawności, samodzielności i poziomu zrozumienia podczas dodatkowej weryfikacji. Konkretna ocena zależy od osiągniętych efektów uczenia się.

Oddanie wcześniej i praca we własnym tempie

Standardowy termin na podstawowy pakiet CV: koniec laboratorium L4. Można oddać cały pakiet już przed kolejnymi zajęciami. Student zainteresowany zakończeniem pracy nad przedmiotem na poziomie 3,0 powinien zaznaczyć to w zgłoszeniu. Po potwierdzeniu przyjęcia rozwiązania nie musi uczestniczyć w dodatkowych konsultacjach projektowych; formalne zasady obecności i zaliczenia zajęć pozostają zgodne z regulaminem uczelni.

Coursera nie jest obowiązkowa ani płatna z założenia. Sam certyfikat nie może być warunkiem dostępu do wyższej oceny. W większości kursów bezpłatny podgląd obejmuje tylko pierwszy moduł; możliwe są też kursy bezpłatne i równoważne materiały. Nie trzeba wykupować subskrypcji ani zakładać kolejnych kont.

Projekt na ocenę 5,0 — Biblioteka

Interaktywna aplikacja do zarządzania autorami i książkami. Frontend: HTML, CSS, JavaScript na GitHub Pages. Backend: automatyczne REST API Supabase z bazą PostgreSQL. Nie wymagamy osobnego serwera Node.js, PHP ani Spring Boot.

Model danych

  • authors: identyfikator, imię i nazwisko autora (lub nazwa), inne pole opcjonalne
  • books: identyfikator, tytuł, rok publikacji, identyfikator autora
  • Relacja jeden autor — wiele książek; klucze główne i obce

Funkcje aplikacji

  • Lista autorów i książek oraz szczegóły
  • Dodawanie, edycja, usuwanie obu typów rekordów (CRUD)
  • Filtrowanie książek według autora lub wyszukiwanie po tytule
  • Formularze z walidacją i komunikatami błędów

Komunikacja z backendem

  • Wywołania REST lub klient Supabase z przeglądarki
  • Obsługa asynchroniczności, ładowania i błędów
  • Operacje GET, POST, PATCH/PUT, DELETE
  • Weryfikacja trwałego zapisu danych po odświeżeniu strony

Obrona indywidualna

  • Prezentacja i omówienie CV oraz aplikacji Biblioteka
  • Pytania z JavaScript, DOM, JSON, HTTP/REST, SQL i relacji w bazie danych
  • Wskazywanie fragmentów kodu i wykonanie wskazanych modyfikacji bez określonego limitu
  • Diagnoza błędów, wyjaśnienie zastosowanych rozwiązań i roli AI

Alternatywa technologiczna: po uzgodnieniu możliwa implementacja równoważnego REST backendu w PHP, Javie/Spring Boot lub Node.js. Kryteria funkcjonalne i obrona są takie same.

Zalecenia, a nie wymagania na ocenę: uwierzytelnianie i RLS nie są obowiązkowe w tym ćwiczeniu. Projekt powinien używać wyłącznie fikcyjnych danych w odrębnej bazie testowej. Nie wolno udostępniać klucza secret ani service_role w publicznym frontendzie; dostępny publicznie klucz publishable/anon służy do wywołań klienta. Publiczne operacje zapisu mogą zostać wykorzystane przez osoby postronne.

Jak oddać pracę przez GitHub

Oddawanie odbywa się przez pull request (PR) do publicznego repozytorium kursu. Zalecane jest wykorzystanie tego samego konta GitHub co na zajęciach Team Project IT. Repozytoria i linki do aplikacji będą publiczne, a oceny pozostaną prywatne.

Preferowany format konta, zgodny z Team Project: vistula-team-project-123456 lub vistula-team-project-123456-abc, gdzie 123456 oznacza przykładowy numer indeksu, a abc jest opcjonalnym trzyliterowym sufiksem. Imię i nazwisko nie są wymagane. Osoba, która nie chce publikować numeru indeksu w loginie, może zgłosić istniejące konto i potwierdzić powiązanie prywatnie w systemie uczelni.

  1. Użyj istniejącego konta GitHub z Team Project lub załóż konto. Rekomendowany format: vistula-team-project-NUMER_INDEKSU (ewentualnie -abc).
  2. Utwórz własne publiczne repozytorium CV z katalogami zad1–zad4 i włącz GitHub Pages.
  3. W repozytorium kursowym przygotuj nowy plik submissions/TWOJ_LOGIN.md. Skopiuj format ze wzoru zgłoszenia.
  4. Wpisz login GitHub, link do repozytorium, link do działającego CV i wybraną ścieżkę oceny. Numer indeksu może występować w loginie, natomiast nie publikuj telefonu, adresu ani certyfikatów z danymi osobowymi.
  5. Zrób fork repozytorium kursu i dodaj plik w swoim forku, następnie otwórz PR do gałęzi main tego repozytorium. Bez uprawnień zapisu jest to normalny sposób zgłoszenia. Zgłoszenie jest złożone już po utworzeniu PR. Prowadzący nie musi go scalać (merge), aby sprawdzić linki i zaliczyć pracę.
  6. Jeśli login nie zawiera numeru indeksu, potwierdź powiązanie z kontem uczelnianym prywatnie, podając login GitHub i URL PR. Sam numer w loginie nie potwierdza tożsamości.

Najczęstsze pytania

Czy można korzystać z AI?

Tak. Na 3,0 liczy się kompletność i działanie. Na 4,0 i 5,0 odbywa się obrona: pytania z teorii, wyjaśnienie kodu oraz modyfikacje i debugowanie według poleceń prowadzącego.

Czy moje CV musi być prawdziwe?

Nie. Zalecane są fikcyjne dane. Nie publikuj prywatnego numeru telefonu, adresu czy innych wrażliwych informacji.

Czy muszę zapłacić za Courserę?

Nie. Dostępna jest bezpłatna ścieżka równoważnej nauki. Sam podgląd pierwszego modułu Coursery nie oznacza ukończenia całego kursu. Na 4,0 obowiązuje także obrona wiedzy i projektu CV.

Czy mogę oddać wcześniej?

Tak. Pełny zestaw CV można oddać przed L4. Po zaakceptowaniu projektu można zamknąć ścieżkę podstawową, a udział w dalszych konsultacjach zależy od zasad uczelni.
